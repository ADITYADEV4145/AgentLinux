# First-run troubleshooting and compatibility

Run `agent-linux version --json`, `doctor --json`, `status --json`, then bounded `logs --backend`. Redact any private state/logs before sharing. Do not attach VM images, control keys, provisioning YAML, full screen captures, secret-bearing commands or personal project files to issues.

| Problem | Action |
| --- | --- |
| Unsupported OS/architecture | Local backend requires Apple silicon. macOS 26.5 (25F71) is tested; macOS 14+ is a development target only. Intel, Linux host, Windows and nested-virtualization setups are unsupported. Linux ARM64 is the guest target, not a working host backend. |
| Missing Lima/wrong version | Install reviewed external Lima **2.2.1** and use `--lima /absolute/path/to/limactl` consistently, or deliberately make that runtime available on PATH. No QEMU fallback or silent runtime upgrade. |
| Missing guest helper | Install the complete bundle or `make build`. Keep both artifacts in their version directory; copying only the host CLI is insufficient. `doctor` verifies sibling helper format; a real handshake establishes actual guest version. |
| Virtualization query denied | Run outside a restricted sandbox; verify hardware virtualization and macOS permissions. Use the original supported Lima/VZ executable. Do not disable SIP/Gatekeeper, change system settings, or add arbitrary entitlements as a blind workaround. |
| Private path/permission error | Use an application-owned 0700 directory with no symlink ancestors; never home/project itself. Resolve `/tmp` to `/private/tmp` on macOS when selecting explicit file-copy/test state paths. Do not recursively chmod a home/project tree. Inspect ownership/marker errors rather than adopting unrelated files. |
| Disk space | Default creation requires **30 GiB available**: 24-GiB logical guest disk plus 6-GiB conversion/headroom. Preflight is conservative; sparse physical usage differs and grows. Runtime/downloads/package caches need space too. Stop/export/delete only selected disposable VMs explicitly. Do not run global Lima prune/delete. |
| Long first startup | Image download and guest package provisioning require Internet and can take minutes. stderr shows bytes/stages/heartbeat; stdout JSON remains machine readable. `--timeout` is a deadline, not promised boot time. Inspect logs/status after interruption; do not assume process launch means ready. |
| Pinned image unavailable/hash mismatch | No daily/latest fallback. Retry a network error or review/select a dated trusted custom local image with explicit SHA-512. Do not bypass verification or use an unreviewed checksum from the failing channel. |
| Apt/DNS/proxy failure | Creation needs reachable Debian repositories. The host proxy environment is deliberately not propagated. Existing successfully provisioned disks skip apt on normal resume, but fully offline host boot has not been validated and no offline/isolation mode is offered. |
| Stale state/interruption | `status` reconciles actual runtime and guest handshake. Retry ordinary `up --local` without creation flags. A missing recorded disk is an error, not automatic data recreation. Interrupted deletion requires explicit delete/reset with the original ID. |
| MACHINE_BUSY | Another lifecycle/capture/action holds the machine lock. Wait/retry status/screenshot safely; do not blindly replay a mutation whose outcome is unknown. A busy error is not evidence that the machine stopped. |
| Desktop unavailable | Guest must have Xfce/Xvfb and panel ready, not just SSH. Inspect backend logs, restart the selected VM, and use a new/reset guest explicitly if its installed recipe/helper is old. Old disks are not patched implicitly. |
| Blank/unsupported terminal | Kitty **0.50.0** on macOS 26.5 is the tested graphics target. No tmux/screen support. Other terminals use the live loopback browser fallback; `view --web` forces it. The tested fallback is Chrome **156.0.8078.80**; native Safari and broad browser/terminal matrices are untested. See viewer.md. |
| Gatekeeper/quarantine | This RC is source-built, publisher-unsigned/ad-hoc and not notarized. No clean-Mac downloaded-binary acceptance exists. Inspect source/build locally; follow Apple policy rather than disabling host protections globally. |
| Copies fail | Explicit regular files only, no symlink/hardlink/special files, at most 4 MiB. Existing outputs never overwrite. Guest helper 0.5.0 is needed. See file-transfer.md for archives and partial cleanup. |

The current Mac is a development machine with existing tools/caches and previous VM testing. It is **not a clean-Mac claim**. Before a wider release, use a clean supported Mac/user account and verify prerequisite installation, source build, package hashes/signing policy, doctor, uncached image download, actual guest handshake, MCP client configuration, real desktop viewing, copy round trip, stop/resume/persistence, explicit reset, selected deletion, tool uninstall and unchanged unrelated files/shell settings. Record hardware/software versions, elapsed time, network/storage conditions and any permission prompt. Test installed/quarantined downloaded artifacts only after an authentic release process exists; this phase publishes none.

Phase 6: use `agent-linux start` for boot plus human viewer, F2 for input handoff, Ctrl+] to leave Linux running. If an agent receives INPUT_OWNED, give control back in the viewer; don't loop blind actions. After a disconnect or desktop restart, observe and explicitly take control again. In terminal applications, choose terminal paste (F3) if auto-detection is wrong. A fullscreen browser may hide its address bar: inspect state, send guest F11 and observe before navigating. New fixture startup still depends on Debian/APT networking; image downloads have bounded deadlines and verified hashes. Interrupted setup can be retried in the same owned namespace; never delete unrelated files to recover it.

Phase 8 first-run guidance: use `start --view-only` in terminal A for an agent-led demo; configure/connect the agent from terminal B. Interactive `start` initially owns input, so F2 handoff is required before agent/copy mutations. The current build pins Go 1.26.9 and may fetch that authenticated toolchain if absent; it changes no global Go/PATH. Chrome 156 human widget acceptance now covers actual guest clicking, Unicode text, guest save shortcut and handoff, while broad accessibility/IME/browser testing remains pending. View [the launch report](launch-readiness.md) for current gates.
